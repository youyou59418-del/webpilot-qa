# 系统架构

WebPilot-QA 由模型推理层、任务控制面、浏览器执行层、验证层和证据层组成。

## 核心流程

1. 用户在中文控制台提交自然语言目标和受控网页地址。
2. API 创建任务记录，写入 PostgreSQL，并向 Redis 发送队列唤醒信号。
3. Worker 获取任务，通过 OpenAI 兼容接口调用本地 Qwen 模型生成计划和下一步动作。
4. 浏览器运行时仅执行白名单工具；每次页面变化后更新语义观察与短生命周期引用。
5. 独立验证器读取真实页面状态，判断成功、失败或需要恢复。
6. 高风险动作进入审批状态；批准后才允许继续执行。
7. 任务事件、截图、最终结果和 Playwright Trace 被保存为可追溯产物。

## 关键设计取舍

- **结构化观察优于原始选择器**：模型看到的是当前交互语义，而不是可直接执行的 CSS/XPath。
- **验证器独立于模型**：页面静态文本不能单独证明任务完成，优先检查输入值、勾选状态、购物车数量等真实状态。
- **恢复必须有上限**：恢复与自愈定位可提高鲁棒性，但应限制预算，避免无休止重试。
- **持久化事实与队列解耦**：PostgreSQL 是任务状态和事件事实来源；Redis 用于任务唤醒而非唯一状态存储。
- **受控基准优先**：ShopBench 可重置、可验证，适合形成可比较的工程证据；不把真实网站演示误作通用能力证明。
