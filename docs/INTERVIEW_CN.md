# 面试说明

## 建议用一句话介绍项目

我实现了一个可验证的浏览器智能体：模型负责规划和调用受限浏览器工具，验证器负责检查真实页面状态，任务过程通过 PostgreSQL、Redis、事件流、截图和 Trace 实现可追溯。

## 高频追问

### 为什么不直接让模型判断任务是否成功？

模型可能把页面中的默认文本、历史文本或无关文本误认为成功。因此验证器读取真实控件状态，例如输入值、勾选状态、购物车数量和指定商品是否存在。

### PostgreSQL 与 Redis 为什么同时使用？

PostgreSQL 保存可恢复的任务状态和事件，是事实来源；Redis 仅用于队列唤醒。即使 Redis 消息丢失或 Worker 重启，也能依据持久化状态恢复任务。

### 安全审批解决什么问题？

风险不应由模型的自我判断承担。高风险动作和敏感输入被动作门控层拦截，产生语义指纹后等待人工批准。

### 如何解读项目指标？

只将 `live_model` 报告视为模型执行证据；区分严格 100 任务诊断基线、组件消融、离线测试和两条 Demo 回归。不能把 2/2 Demo 回归写成整体成功率。

## 投递定位

适合投递 AI Agent 工程、LLM 应用工程、智能测试 Agent、AI 平台后端等岗位。面试时重点说明工程闭环、状态验证、安全边界、任务恢复和评测方法，而不是宣称已实现高成功率通用网页代理。
